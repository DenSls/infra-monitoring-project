# Анализ сетевого трафика.

## Дамп

Файл захвата: [`httpbin-capture.pcapng`](httpbin-capture.pcapng).

## Результаты

В дампе найдено TLS-соединение с узлом `httpbin.org`. Имя узла видно в TLS SNI, кадр 751. Соединение с сервером установлено по TCP к адресу `44.209.237.184:443`.

Захват также показывает локальный маршрут через промежуточный узел:

- `172.19.0.2` — клиентская сторона локального соединения;
- `172.19.0.1` — локальный промежуточный узел;
- `44.209.237.184` — удалённый адрес назначения `httpbin.org`.

| Параметр | Результат |
| --- | --- |
| Запрос | `curl https://httpbin.org/get` |
| IP-адреса обмена | `172.19.0.2` → `172.19.0.1` → `44.209.237.184` |
| HTTP-метод | `GET` — метод по умолчанию для этой команды `curl` |
| Код ответа | `200` — получен отдельным повторным запросом (не из дампа) |

## Ограничение анализа

Запрос использует HTTPS. В захвате видны TLS-рукопожатие и имя узла `httpbin.org`, но содержимое HTTP-запроса и ответа зашифровано. Поэтому Wireshark не показывает URI `/get`, HTTP-метод или код ответа. В дампе нет распознанных открытых пакетов `http.request` или `http.response`.

Код `200` проверен отдельным повторным запросом в Bash:

```bash
curl -sS -o /dev/null -w 'HTTP status: %{http_code}' https://httpbin.org/get
```

Результат повторного запроса подтверждает статус ответа в исходном дампе.
